## Concrete adaptation candidates and boundaries

### GeoLibre + GeoAI

Adapt the **runtime explanation and exchange pattern** in [lab 06](https://github.com/jltobias/JupyterLite-GeoLibre-GeoAI/blob/dda3a4667a1267b5ac4858723c46d8c0c82cb7a6/book/notebooks/06_geoai_compatibility.ipynb) and the small [geolibre_lite.py](https://github.com/jltobias/JupyterLite-GeoLibre-GeoAI/blob/dda3a4667a1267b5ac4858723c46d8c0c82cb7a6/book/notebooks/geolibre_lite.py) adapter: upstream `geolibre.Map` starts a localhost server, while `LiteMap` uses native project/layer builders with a hosted viewer and embed/postMessage bridge. The adapter imports `anywidget`, `traitlets` and GeoLibre; notebooks install `geolibre==3.0.0`. [build_lite.py](https://github.com/jltobias/JupyterLite-GeoLibre-GeoAI/blob/dda3a4667a1267b5ac4858723c46d8c0c82cb7a6/scripts/build_lite.py) explicitly discovers kernel/widget extension paths and validates the built kernel, useful for Windows builds. The browser route still requires the hosted viewer and remote sources.

The [DBSCAN cholera lesson](https://github.com/jltobias/JupyterLite-GeoLibre-GeoAI/blob/dda3a4667a1267b5ac4858723c46d8c0c82cb7a6/book/notebooks/21_cholera_geoai_first_steps.ipynb) offers map → spatial clustering → contextual evidence, with limits on causation and population denominators. Its [data note](https://github.com/jltobias/JupyterLite-GeoLibre-GeoAI/blob/dda3a4667a1267b5ac4858723c46d8c0c82cb7a6/book/notebooks/data/cholera/README.md) pins PHI-Case-Studies commit `476f6dd5a8430e6eb823e79614fda1d7e12a78fb`, and the actual [GPL-3.0 file](https://github.com/jltobias/JupyterLite-GeoLibre-GeoAI/blob/dda3a4667a1267b5ac4858723c46d8c0c82cb7a6/book/notebooks/data/cholera/LICENSE) is bundled. Do not silently fold those CSVs into a differently licensed course dataset. [DATA_SOURCES.md](https://github.com/jltobias/JupyterLite-GeoLibre-GeoAI/blob/dda3a4667a1267b5ac4858723c46d8c0c82cb7a6/DATA_SOURCES.md) distinguishes many real remote sources from synthetic rainfall, image-change and terrain fixtures, and supplied/Esri/presentation graphics with separate rights. PyTorch-heavy `geoai-py` is an external CPython/GPU continuation; package availability is not proof that a capability works in Pyodide. Prefer new course examples and links until repository-wide reuse scope is resolved.

[Build requirements](https://github.com/jltobias/JupyterLite-RustGIS/blob/64ee4e32222c07006ab28a634b759d985a002bda/requirements.txt) pin Lite 0.8.2/kernel 0.8.3 and Book 1; the project lacks a general license.

## Implications for the expansion

- **Core course:** use small, versioned, license-cleared observed datasets for the 100 visualization methods; keep synthetic fixtures visibly labeled and retain source/year/unit/denominator fields. An example's runnable code does not establish observational validity.
- **Companion GIS:** prefer standalone browser JS maps and explicit GeoJSON/STAC handoffs. Distinguish Pyodide, xeus-python/JupyterGIS, external hosted viewers and native/GPU continuation routes. Test the selected runtime and deployment subpath rather than merging incompatible build recipes.
- **Data and rights:** record dataset-level license, attribution, exact source revision/retrieval date, transformations, checksums and access restrictions. Preserve separate notices for any adapted component; resolve unknown/limited rights before redistribution. Repository licenses cannot sublicense external datasets.
- **Access and persistence:** initial package/CDN downloads, CORS, WebGL, provider availability, authentication and browser storage remain visible constraints. Provide local small data, readable results and 2D/table fallbacks; prompt users to download notebook edits and exports.

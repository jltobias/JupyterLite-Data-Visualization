# Browser geospatial tool compatibility and licenses

Checked 2026-10-28 against upstream source and official documentation. This is an investigation for a separate static geospatial lab; these capabilities have **not** been smoke-tested in this repository. Existing baseline: JupyterLite 0.7.6, Pyodide 0.29.3, JupyterLab 4.5, Jupyter Book 1.0.4.post1. Build-machine Python dependencies do not automatically become browser-kernel packages.

## Hosting, data access and frontend constraints

- **Pyodide is a browser sandbox.** Pure-Python wheels and compatible Emscripten/WASM wheels can be loaded; normal Windows/Linux/macOS binary wheels cannot. Pyodide 0.29.3 does not provide working ordinary sockets, Python threading or multiprocessing. Browser network requests still obey CORS. [Package loading](https://pyodide.org/en/0.29.3/usage/loading-packages.html), [compatibility](https://pyodide.org/en/0.29.3/usage/wasm-constraints.html).
- **Widgets need two installations.** If a later lesson uses anywidget/ipywidgets, include compatible frontend assets in the JupyterLite build and matching Python packages in the browser kernel; runtime `%pip` alone does not add frontend extensions. The current requirements do not declare this stack. A static iframe/HTML scene needs no such extension. [JupyterLite extension packaging](https://jupyterlite.readthedocs.io/en/stable/howto/configure/simple_extensions.html).
- **COG is a storage layout, not a server.** Tiled overviews and HTTP byte ranges enable partial reads. Before adopting a remote COG/PMTiles/GeoParquet asset, test an actual `Range` GET from the deployed page: require an appropriate `206`/`Content-Range` response and usable CORS; expose headers the chosen reader needs. A server that returns the whole file can defeat the memory/performance plan. Ordinary deck.gl does not automatically turn a COG into a raster scene: add and test a suitable reader or pre-render small raster tiles. [COG mechanics](https://cogeo.org/in-depth.html), [GeoLibre remote requirements](https://geolibre.app/user-guide/embedding/#open-remote-data).
- **STAC is discovery metadata.** Static catalogs can be hosted as JSON; live STAC search requires an API service. An accessible catalog does not guarantee that its imagery is public, CORS-enabled or durable. Check each asset, its license and any expiring signed URL independently. Do not commit temporary Planetary Computer URLs into a durable project. [STAC specification](https://stacspec.org/en/about/stac-spec/), [RustGIS signing limits](https://rustgis.app/user-guide/web-data/).
- **Capability fallback is part of the scene.** Detect missing WebGL2, GPU context loss and failed resources; offer the same data in a table/2D figure and a download. WebGPU should be an explicit optional experiment. Lazy-load the hosted GIS workspaces and extra interpreters. Public demos and upstream feature lists establish integration possibilities, not this lab's tested compatibility, uptime or performance.

## Inference without secrets and model licensing

The dependable default is a small published GeoAI result with its native reproduction notebook and a provenance manifest. A browser lesson may inspect the imagery, change display thresholds and compare masks, but must identify precomputed results. To demonstrate **new local inference**, use a separately tested ONNX graph, exact preprocessing/postprocessing and a small public image. GeoAI export does not guarantee ONNX Runtime Web operator support or correct georeferencing.

GeoLibre's separate browser “Segment Everything” implementation is a useful candidate: [its source](https://github.com/opengeos/GeoLibre/blob/main/apps/geolibre-desktop/src/lib/segment-models.ts) pins about 23 MB + 16 MB of SlimSAM ONNX files for CPU/WASM; the [publisher's model card](https://huggingface.co/Xenova/slimsam-77-uniform) declares Apache-2.0. Make model download user-initiated, record the immutable revision/hash and license, and retain a cached-output fallback. ONNX Runtime Web can force single-thread WASM with `ort.env.wasm.numThreads = 1`, avoiding a requirement for multithread isolation; pin its JS and WASM to the same build. [Runtime options](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html).

The other similarly named paths have different conditions:

| Path | Boundary / licensing decision |
| --- | --- |
| GeoLibre AI Segmentation / SamGeo / SAM 3 | The desktop dialog proxies to a separate `samgeo-api` server; its browser SamGeo plugin also uploads images to a configured server. CUDA is recommended, CPU possible but slow. SAM 3 has Meta's **custom SAM License**, not GeoLibre's MIT license. Exclude from the default serverless path. [Architecture and uploads](https://geolibre.app/user-guide/segmentation/), [SAM 3 license](https://github.com/facebookresearch/sam3/blob/main/LICENSE). |
| GeoLibre built-in YOLO detection | [The model registry](https://github.com/opengeos/GeoLibre/blob/main/apps/geolibre-desktop/src/lib/detection-models.ts) identifies AGPL-3.0 Ultralytics weights served from third-party demo repositories; their demo code's MIT license does not relicense the weights. It also warns COCO models perform poorly on overhead imagery. Do not silently bundle or represent these as a permissively licensed geospatial model. |
| LLM assistants, Earth Engine, private datasets | Provider credentials/authentication and service terms are separate from application code licenses. GitHub Pages cannot keep an API key secret. Leave assistant/model-server features unconfigured in the public lab; optional native reproduction may use the learner's own environment. |

Upstream code licenses do not license source datasets, imagery, basemaps, models or all plugins. Maintain per-asset provenance and attribution; include applicable license/NOTICE text when redistributing third-party code or weights, and mark modifications where required. **The owner has not selected a license for project-authored content; this investigation makes no license grant for that content.**

## Recommended implementation order

1. Build a separate locally rendered deck.gl 2D/3D scene and an accessible story around small, same-origin public-health/environment extracts. Keep geometry joins and data units inspectable in the existing browser Python lab; publish a data/provenance download.
2. Add real GeoLibre and RustGIS projects using those same extracts, with hosted-workspace embeds and downloadable project files. Label their execution origin and runtime limits. Keep the core story usable if either external app is unavailable; use a pinned self-hosted build only when its added deployment weight and messaging requirements are justified.
3. Add the standalone PyScript transformation lesson with explicit runtime pins. Add GeoAI's native reproduction and precomputed outputs; only describe browser AI execution once an optional licensed ONNX path passes a real browser test.

Acceptance evidence should show: a fresh deployed-page load, successful local controls and 2D/3D rendering, one exported artifact per GIS workspace, actual CORS/range checks for remote rasters, graceful GPU/network fallbacks, and the specific computation performed in Python or ONNX. A gallery hyperlink alone does not satisfy integration.
